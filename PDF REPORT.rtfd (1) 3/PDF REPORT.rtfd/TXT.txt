Task B — Written Part
A web page is a text document structured with HTML tags that assign meaning to raw content. When a browser opens our project files, it parses the code top to bottom, building a Document Object Model (DOM) tree. It interprets these elements to render tables, lists, and forms visually on the screen without needing external software.
Across all six files of our website project (index.html, colophon.html, branches.html, membership.html, schedule.html, and facilities.html), we strictly chose semantic tags over generic <div> containers to ensure proper accessibility and structure. First, in schedule.html, I used <nav> for the site links instead of a <div> so screen readers immediately identify the primary navigation block. Second, in facilities.html, I wrapped the "Free Weights" section in an <article> because this specific equipment breakdown is self-contained, and utilized an <aside> for the maintenance protocol. Third, across the pages developed by my partner like membership.html, we incorporated advanced semantic structures such as description lists (<dl>, <dt>, <dd>) for subscription types and structured data tables (<table> with <thead>, <tbody>, and scope attributes) for pricing plans.
Currently, clicking "TRANSMIT REQUEST" in the schedule.html form triggers client-side validation for required fields like email and date. Because the action attribute is set to # and there is no server-side backend connected yet, a successful click simply refreshes the page, and the input data is discarded without being processed.
